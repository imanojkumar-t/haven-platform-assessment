# B0 — The `count` trap

What does `terraform plan` show when a middle landlord account is removed from the list? Why is
that dangerous here? What's the fix?

<!-- Your answer here -->

count identifies resource by their postion (0,1,2,3) in a list. for example haven has created landlords a,b,c if a landlord b is removed, landlord c moves from postion 2 to postion 1 thn terrafrom changes the plan and replace c postion and deletes the old bucket at postion 2 which results data loss 

    so instead of "count" we use "for_each", as it identifies
    resources by landlord account id instead of their position even if landlord b is removed terraform only b bucket and keep a and c resource.

#here the correct way to identify the issue 

resource "aws_s3_bucket" "landlord_media" {
  for_each  = toset(var.landlord_accounts)
  bucket = "haven-media-${each.key}"

  tags = {
    landlord_account_id = each.key
  }
}

variable "landlord_accounts" {
  type        = list(string)
  description = "Landlord account IDs, in the order their infra was originally provisioned."
  default     = ["la-001", "la-002", "la-003", "la-004"]
}
